# 模板（交接、决策、验收、发布）

复制后填空，删掉不需要的行；方括号内提示要删掉再交付。

## 一页范围书

项目的第一份产物，也是后面所有阶段门的参照。

```text
一句话核心体验：（玩家在什么处境下做什么、获得什么感受）
目标玩家与场景：（谁、在什么设备与时间玩）
目标平台与设备矩阵：
体量上限：（用「内容量单位 + 可投入工时」两个度量写，避免只写内容数）
非目标清单（本版本明确不做）：
  - …
成败判据（怎么算做成了，可观察、可验证）：
  - …
关键假设与风险初判：（登记到风险探针清单）
```

使用要点：非目标清单与成败判据比「做什么」更重要；体量数字属项目专属值，由项目档案提供，不写进方法论。

## 闭环图

阶段 2 的核心产物，一行文字链就够，不必动用画图工具。

```text
输入 → 状态变化 → 玩家可感知的反馈 → 收益 → 下一个目标 → 回到输入
逐段标注：玩家需要什么信息才能决定下一步；缺的信息就是教学或界面的缺口。
```

## 阶段门评审记录

```text
阶段 / 日期：
输入产物：（文件路径、构建、数据表）
完成条件逐条证据：条件 → 命令或步骤 → 版本 → 设备或环境 → 结果
未满足项与缺口：缺口 → 待办 → 补齐阶段 → 负责人
三轨对齐：玩法轨（玩家能感知到什么）／技术轨（改动落在哪些文件与数据）／质量轨（怎么证明没坏）
结论：通过 / 带条件通过（附条件） / 不通过（退回阶段与理由）
```

使用要点：没有证据的条件按未满足处理；带条件通过的每一项都必须指定补齐阶段。

## 任务交接

用于把一件事交给另一个窗口、另一个人或未来的自己。

```text
交接标题：
负责范围：（做什么、不做什么）
当前状态：未开始 / 进行中 / 待验收 / 已完成
产物：（文件路径、构建、数据表、文档）
验收条件：（逐条可执行、可观察；写明用哪条命令或哪个设备验证）
复现步骤：（从干净环境开始，逐步写，能被别人独立执行）
已知问题与未决项：
依赖与阻塞：（外部依赖、需要谁配合、等待中的决定）
下一步建议：
```

使用要点：验收条件是这份模板的核心，必须是别人能独立执行的检查；不接受「功能正常」「已优化」这类无法验证的描述。状态填「已完成」时，验收条件必须是已经执行过的。

## 设计决策记录

用于任何会影响后续实现的取舍（玩法规则、数据结构、平台支持、性能方案、范围变更）。

```text
决策编号 / 标题：
日期：
状态：提议 / 已定 / 已废弃
背景与问题：（要解决什么，为什么现在要定）
约束：（平台、性能预算、体量、存档兼容、日程、团队能力）
选项：（列全候选，含「不做」）
决定：
理由：
影响与代价：（要改哪些文件与数据、要放弃什么、要补哪些文档）
被否决的选项为什么否决：
复查条件：（出现什么情况要重新评估，例如性能数据、真机结论、玩家反馈）
```

使用要点：一条决策只记一件事；已定决策被推翻时改状态并写新的复查结论，不要悄悄改正文。

## 功能验收

用于把一个功能从「写完了」推进到「验证过了」。

```text
功能：
版本 / 构建标识：
验收环境：（设备、系统、输入方式、网络与电量条件）
前置数据：（存档、账号、数据表版本）
步骤与预期：
  1. [操作] → [预期结果]
  2. ...
边界与异常用例：（空数据、极值、断网、切后台、重复操作、中途取消、回退）
兼容性：（旧存档、低端设备、低版本系统、不同输入方式）
结论：通过 / 带条件通过（列出条件与补齐阶段）/ 不通过（列出阻塞项）
证据：（命令与输出、截图、日志、记录表位置）
未覆盖项：（没测的部分与原因，及如何记录）
```

使用要点：边界与异常用例是最容易漏掉的部分，逐条对照风险清单填；结论里不允许出现没有证据的通过项。

## 发布检查

用于封版前的最后一道门。

```text
版本号 / 构建标识：
目标平台与渠道：
发布范围：（新内容、修复项、已知不做的事）

阻塞项（必须全绿）：
  - 构建可安装、可启动、可卸载
  - 主流程从头走通，无崩溃、无卡死
  - 存档读写与旧档兼容正常
  - 目标设备性能达标（分位帧率、内存峰值、加载时间）
  - 平台与渠道资料齐备（图标、截图、描述、隐私与合规、权限说明）
  - 商店页上线、审核与认证周期已按倒排启动（不能留到发布周）
  - 版本号与构建可追溯，发布包不进入代码仓库

带病发布项（允许非阻塞项带病，但必须记录）：
  - 问题 / 影响面 / 触发条件 / 规避方式 / 记录位置

回滚方案：
  - 触发条件、回滚到哪个版本、由谁执行、多久内执行

产物与留存：（发布包、符号文件、发布说明、已知问题清单）
未验证与已知缺口：（没有真机数据或没覆盖到的功能逐条列出，不混进全绿项）
签署：（谁确认、时间）
```

使用要点：把「带病发布项」当成正式产物维护，而不是口头承诺；任何一项阻塞项不绿就不发布。非阻塞的判据是「能用已记录的规避方式绕过，且不影响主流程走完」，绕不过去的一律算阻塞；发布形态（正式发售／抢先体验／内测）对应的检查表差异写进项目档案，不现场临时放宽。

## 存档迁移说明

阶段 9 的产物：记录旧档如何变成新档。

```text
结构版本号规则：（只增；每次结构变更必须进位）
权威定义位置：
迁移链：
  v1 → v2：（字段变化、默认值、语义变化）
  v2 → v3：…
迁移入口：（所有读档只走这一处）
旧档样本来源：（真实历史档，不靠自造）
读档测试用例：缺字段 / 多字段 / 损坏档 / 旧版本号 / 写入中断
已知不可迁移的情况与宣告方式：（明确告知，不静默重置）
```

## 附：风险探针结论

```text
问题：（一句话）
假设：（现在相信什么）
做法：（最小可运行范围、时间盒、放弃点）
观测：（条件、数据、重复次数、原始输出位置）
结论：可行 / 不可行 / 可行但代价是…
对设计或范围的影响：（改了哪条规则、砍了什么、范围书哪一节要更新）
后续动作与期限：
探针代码处置：删除 / 转为长期工具（给出入口与文档位置）
```

## 附：项目档案

项目专属规则的唯一落点。本方法论不保存这些值。

```text
项目名 / 一句话核心体验：
引擎与版本：
品类与目标玩家：
目标平台与设备矩阵：
性能预算：（帧率、内存、包体、加载时间）
存档格式与兼容策略：（字段权威定义在哪个文件）
数据与内容组织：（数据表位置、新增同类内容的扩展方式）
自检与工具：（一条命令的入口、报告与产物位置、长期工具清单）
验收阈值与发布渠道：
本地约定：（命名、目录、提交信息、产物管理）
```
