# 验证与风险（探针、自动化、模拟、真机）

`SKILL.md` 里阶段 5、6、7、8 的具体做法。

## 风险探针

**什么时候做**：出现下面任一类未知项时插队执行，不要先排期再验证。

- 新引擎、新平台能力、新 SDK 或审核政策。
- 目标设备上的性能上限（帧率、内存、加载时间、发热）。
- 关键技术未知（多人联网、存档迁移、大场景、复杂 UI 布局）。
- 玩法假设（这个循环是否好玩、玩家是否看得懂）。
- 第三方服务可用性与成本。

**探针规格**：

- 只回答一个问题，问题用一句话写清。
- 最小可运行：用最少的代码与资源让不确定性暴露。
- 有明确时间盒与放弃点，超时就下结论。
- 可丢弃：不与主线代码纠缠，不进入发布构建。
- 观测可复现：同一条件下重复得到同一结论。
- 结论写回设计或范围，而不是只留在对话里。

**结论格式**：问题 / 假设 / 做法与时间盒 / 观测（条件、数据、重复次数）/ 结论（可行、不可行、可行但代价是什么）/ 对设计或范围的影响 / 后续动作与期限 / 探针代码处置。模板见 [templates.md](templates.md)。

**处置**：结论不利就改设计或砍功能，不硬推；探针代码转为长期工具（要有入口与文档）或删除。

## 自动化验证

**分层**（从便宜到贵，按需组合）：

1. 数据完整性：引用有效、必填字段、取值范围、互斥关系。
2. 规则契约：核心规则函数在给定输入下的输出与不变量。
3. 流程冒烟：能启动、能进主界面、能完成一次核心循环、能存档并重载。
4. 结构与几何：界面面板尺寸与锚点、父子关系等渲染前的结构断言。
5. 存档往返：存 → 读 → 对比；旧版本存档读入。

**设计要求**：

- 一条命令跑完，退出码可信（全通过为 0）。
- 失败可复现：固定随机种子、隔离运行目录、不依赖本地残留状态。
- 只清理自己创建的数据目录，不动用户与系统数据。
- 断言覆盖行为与不变量，不做字符串匹配式的假检查。
- 新增或修复功能同步补断言；不为过检删除断言或放宽条件。
- 与检查逻辑无关的环境噪音（引擎回收顺序等）要在文档里写明原因，不许用过滤输出掩盖。
- 检查分层执行：快检查每次改完都跑，慢检查（全量模拟、真机）按节点跑。
- 用于复现问题的临时探针，问题查清后删除；长期工具与临时探针分开管理。
- 无法自动化的项（手感、表现、平台交互）登记为人工检查项，写进验收清单。
- 判断检查是否脆弱：需要人工判读输出、依赖本机残留状态、断言绑定文案而非行为、只能在特定机器通过、慢到被人跳过——出现任一条先修检查，不要放宽断言。
- 没有任何自检入口的项目，最低起步集是三项：启动冒烟（启动 → 进主界面 → 完成一次核心循环 → 存档 → 重载）、存档往返、数据完整性；先把退出码做到可信，再谈覆盖率。

## 数值模拟

**定位**：发现问题，不替代手感判断，不自动改数据。

**做法**：

- 指标定义清楚：谁赢、多久结束、资源消耗分布、极端组合的表现。
- 固定随机种子与样本量，报告里写清全部参数，保证跨版本可比。
- 看分布与分位，不只看均值；重点看最差与最优组合。
- 模拟器必须调用与游戏相同的规则实现，否则结论无意义。
- 报告随代码入库，用于对比不同版本的配平结论。
- 模拟结论与试玩冲突时，以设计意图与手感为准，改模型或改指标。

**越界行为**：脚本自动写回数值数据；把模拟结果当验收结论；用模拟代替真机或试玩。

## 外部能力降级检查

第三方、平台与网络能力接入时逐条对照：

- 可用性检测：断网、无账号、服务不可用、版本不兼容能被识别，而不是超时挂起。
- 超时上限：每次调用有明确上限，不用「一直等」代替失败。
- 重试上限与退避：有限次重试，失败后进入离线态，而不是反复重试。
- 离线态行为：缺失该能力时主流程仍能走完，入口可绕过或明确置灰。
- 错误可见：失败要有可见状态与重试入口，不静默失败，也不静默降级到错误数据。
- 缓存策略：可缓存的结果离线可用，并说明过期与覆盖规则。
- 成本与配额：调用量、费用、配额的边界写进项目档案。

## 目标设备验收

**设备矩阵**：机型档位（低端 / 中端 / 高端）、系统版本、输入方式（含同时多输入源，例如同屏多人）、屏幕尺寸与形态、有无外设。

**条件矩阵**：按目标平台真实的生命周期与中断模型推导，不要照抄别的平台。移动端示例：弱网、断网、低电量、低存储、切后台、锁屏、来电与通知打断、横竖屏切换、权限未授权或被回收。桌面端示例：窗口与全屏切换、分辨率与比例变化、多显示器、手柄热插拔、平台覆盖层、离线模式、系统级暂停。主机端示例：挂起与恢复、账号与存档切换、平台认证要求。项目实际采用的维度写进项目档案的验收清单。

**记录内容**：设备与系统、构建版本、操作步骤、观测结果、结论。

**性能采集**：平均与分位帧率、卡顿次数、内存峰值、加载时间、发热与耗电，全部在目标设备上取数。

**平台流程**：登录、支付、成就、云存档、隐私与权限弹窗等必须在真实环境走一遍。有平台云同步时，把与本地档的冲突当正式用例：本地新／远端旧、远端覆盖本地、同步中断、换设备登录。

**阻断判据**：崩溃、卡死、输入不可用、主流程走不通、性能明显不达标。

**纪律**：没有真机数据的项不算通过；确实无法覆盖的设备或场景，显式记录为已知缺口，不要默认通过。

## 回归与冒烟

- **触发条件**：数据表改动、核心规则改动、存档结构改动、平台相关代码改动。
- **冒烟范围**：启动 → 进入核心循环 → 保存 → 重载。
- **缺陷分级**：阻塞（不能玩）／严重（体验断裂）／一般／记录。
- **修复纪律**：修完缺陷补一条断言，防止同因复现。

## 证据标准

任何「已完成」「已修复」「已验证」的结论都要带齐：命令或步骤、执行版本、设备或环境、观测结果。缺任一项按未验证处理。
